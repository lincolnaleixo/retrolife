# Cartridge library

This document specifies the implemented presentation and how to verify it. `plan.md` remains the roadmap and source of completion status. The visual direction comes from the owner's cartridge-carousel reference; final visual acceptance still requires review of the running application.

## Visual specification

The library is a full-window dark showcase rather than a grid of cards. Static studio lighting and a soft ground glow frame the selected physical game medium. The selected object is full size with a slight three-quarter angle. Neighbors recede horizontally and in depth; edges do not wrap or duplicate entries. The camera is controlled by the interface, never a free-orbit viewer.

The integrated header contains the RetroLife wordmark, contextual Back/Box/Details actions, Search and Menu. Menu holds import, controllers, storage, display settings and window actions. Most vertical space belongs to the 3D stage; only the selected title and system remain below it. The console page shows one populated console at a time. Click its artwork to enter the collection. The window has no native titlebar; drag the wordmark area to move it and use F11 or Menu for fullscreen.

Release-pinned neutral models include the SNES NTSC-U shell, western Mega Drive cartridge, standalone PlayStation CD, Nintendo 64 cartridge and NES cartridge. New models are published first in retro-3d-library and consumed unchanged here. The bridge still imports and plays SNES only; a 3D model does not grant emulation, ROM import, or catalog support. Missing SNES assets use the existing procedural cartridge; missing PlayStation models use an annular CD fallback; other missing or unknown systems use a neutral sleeve. Tall cartridge labels fit inside that sleeve without changing their aspect ratio. A fallback is not the acceptance target when verified GLB assets are staged.

Transitions last 220 ms with cubic easing. A new input interrupts the previous transition and targets the new selection immediately. Pointer movement adds at most a few degrees of parallax tilt, and the selected cartridge rests in a gentle idle sway and float so the showcase never looks frozen. Reduce motion removes transitions, idle motion and pointer tilt, while manual inspection stays available with direct, undamped response. Low-power rendering reduces the neighborhood to three models, lowers the internal resolution and disables multisample antialiasing. The text view disables 3D rendering entirely and shows at most seven rows, adapting to available height.

## Controls and everyday use

Import your own `.sfc` or `.smc` files with **Menu → Import ROM**. Successful imports clear an active search and select the newly imported game, while failed imports remain visible as errors. Files continue to use the existing managed local library and battery-save implementation.

The selected cartridge can be inspected directly: drag it to rotate through the full 360° yaw with bounded pitch, zoom with the wheel or a pinch, and reset the framed view with `R`. Dragging the hero never launches or deselects a game.

| Action | Keyboard | Controller | Mouse / trackpad |
| --- | --- | --- | --- |
| Previous / next game | Left / right arrows | D-pad or left stick | Horizontal drag, pan or side arrows |
| Inspect the selected cartridge | Shift + arrows | Right stick | Drag the selected cartridge |
| Zoom inspection | `+` / `-` | Left / right trigger | Wheel or pinch |
| Reset inspection | `R` | Right stick click | — |
| Play selected game | Enter | A | Click the selected cartridge |
| Details | Tab to Details | Focus Details | Top Details action |
| Select a visible neighbor | Arrows | D-pad | Click that cartridge |
| Switch system | Back, then Left/Right | LB / RB | Back, then console side arrows |
| Search | `/` | Y | Search button |
| Back / clear search | Escape | B | Top back arrow / edit Search |
| Change presentation | Tab to Menu | Focus Menu | Menu → Display settings |

The selection is remembered separately for the most recent 32 combinations of system and search. Closing details or returning from gameplay restores the game identity rather than guessing a numeric list position. The last selected game and system, reduced motion, rendering quality and text-view preference are saved locally. The current search itself is not persisted across launches.

## Cartridge artwork

Open a game's details and choose **Choose local cartridge label...**. Only user-selected PNG files are accepted. A PNG must be no larger than 8 MiB and 2048 by 2048 pixels; its signature and dimensions are checked before decoding. Stored artwork is normalized to RGBA and at most 1024 pixels on its longest edge. Failed replacements preserve the previous label.

Labels live in the application's user-data `artwork` directory under the SHA-256 of the game ID. Paths are generated by the application, not derived from game titles. An original neutral label is always available from the title, system and collection index. A per-instance runtime material follows the actual continuous front-label mesh and its folded-top UVs; the separately versioned GLB is not rewritten. Label-proportioned artwork, including verified collection exports, is applied directly to the label surface at up to 2048 pixels with mipmapped anisotropic filtering so the folded top stays crisp at grazing angles. Label textures clamp at their UV borders so filtering cannot pull pixels from the opposite edge into the top fold. The front and rear label surfaces use shared runtime copies of the original full-detail triangles without generated LODs: mesh simplification otherwise distorts UV interpolation and bends letters across the fold. Shell meshes retain their imported LODs; model positions, label UVs, artwork and the pinned GLB are unchanged. Other artwork shapes and neutral labels are composed only when the game or artwork changes, not on every idle frame. SNES keeps its 1024 by 512 canvas; Mega Drive uses 1024 by 927, PlayStation uses 1024 by 1024, Nintendo 64 uses 1024 by 1174, and NES uses 1024 by 1806. New models use their physical label ratios for front and rear artwork; differently shaped images are letterboxed, not stretched. The current approved collection index remains SNES-only, so a same-named title on another platform cannot receive or fetch a SNES label.

The library also resolves approved per-game labels from the public cartridge collection. Matching is local: the committed index at `scripts/library/collection_labels.json` is checked against `assets/cartridges.lock.json` in CI, game titles are normalized and compared on the machine, and title matching never consults the network.

When a matching game has no verified artwork, the **Download approved labels** setting (on by default) allows one user-initiated request for that game's pinned package URLs (front and rear) from the collection's release tag. The downloaded bytes are verified against the committed SHA-256 before they are installed atomically into the user cache (`user://collection-labels`); a mismatch installs nothing. Verified files are never silently replaced: the pinned checksum changes only with a reviewed index update. A verified rear export is painted onto the rear printed-information surface; without one, that surface keeps its unprinted finish. When the setting is off, the collection is unreachable, or verification fails, the neutral title label is used and browsing and play are unaffected. Only the approved package URLs are requested; the library, filenames, hashes and play data are never uploaded, and fetching covers the game being browsed rather than a background sweep of the collection. The staged artwork path for owner validation is excluded from release exports, so release bundles contain no commercial game artwork. A request for a title does reveal that package ID to the download host, which is why fetching is user-initiated and can be disabled entirely.

Dragging the cartridge follows the pointer: dragging right turns the front to the right, dragging down tilts it down, and the smoke pins that direction.

## Organized source library

The model repository stores [neutral templates by console](https://github.com/lincolnaleixo/retro-3d-library/tree/main/assets/templates) and [game reproductions by console and game](https://github.com/lincolnaleixo/retro-3d-library/tree/main/assets/reproductions). These folders contain each asset's documentation, previews and version manifests. Model changes are published there before RetroLife consumes them.

From a checkout of `retro-3d-library`, build the same folder layout with verified release files:

```sh
python3 tools/build_library.py --output dist/library
```

Open `dist/library/index.html` to browse the downloaded library. Each model folder includes its editable Blender source, self-contained GLB, previews, ZIP, release manifest and notices. RetroLife continues to stage the versions pinned by its asset locks through the commands below; downloading this source library does not change those locks.

Organizing the source folders does not change package IDs, immutable release tags or archive checksums. Approved label URLs remain pinned to their original release tag and path. Local previews copy per-model notices from `assets/templates/<console>` and also accept the older `assets/<id>` layout.

## Reproducible model staging

`assets/cartridges.lock.json` pins the neutral `snes-ntsc-u` package at version `0.1.0`, its archive size/hash and the hashes of the unmodified GLB, license, credits and notice. `assets/media-models.lock.json` records the exact published versions, source commits, archive hashes and per-file hashes for Mega Drive, PlayStation, Nintendo 64 and NES. Public release downloads are verified before integration. `scripts/build.sh` prepares all five packages before building the bridge. Each additional model keeps independent notices in its own asset directory.

Nintendo 64 uses the independently published `0.2.0` neutral package; NES remains at `0.1.0`. The N64 refinement smooths the crown and shoulder transitions and adds recessed rear lettering, a continuous connector guide, exposed board substrate and refined Gamebit screws. Its physical envelope and front/rear artwork UV targets remain compatible with the existing profile. The locks select only each unchanged GLB, `LICENSE`, `CREDITS.md` and `NOTICE.md`; neither the Blender sources nor the Super Mario game reproductions enter the application release. Both export presets include every neutral model's license file.

```sh
python3 scripts/prepare-cartridge-assets.py
python3 scripts/prepare-cartridge-assets.py --verify-only
# An offline build can use an already downloaded, checksum-verified release archive:
python3 scripts/prepare-cartridge-assets.py --archive /path/to/snes-ntsc-u-0.1.0.zip
```

Inputs are staged beneath `frontend/godot-ui/assets/cartridges`, which is ignored by Git. No Blender sources, previews, proprietary labels or arbitrary archive members are staged. Validation rejects traversal, links, duplicates, unexpected sizes/checksums, oversized archives and external GLB image/buffer resources. Only a fully verified input set replaces previously staged files. Unchanged files retain their modification times to avoid needless Godot reimports.

For a deliberate code-only/fallback development build, set `RETROLIFE_SKIP_CARTRIDGE_ASSETS=1` before running `scripts/build.sh` with an empty asset stage. This is not the normal release path. Release preparation verifies the pinned stage again and copies its independent notices into the app's license directory. A clean installed app requires no network access to display its included neutral model.

The model's original contributions retain CC BY-NC-ND 4.0. This does not become the license of RetroLife's AGPL application code, and it does not grant rights to Nintendo artwork or other excluded material. Distribution must preserve the separate asset notices and satisfy the asset license or a separately documented permission from its rights holder. No additional license grant is inferred from this integration.

## Local five-model preview

Replacing game artwork preserves the imported paper's normal and roughness maps. The media smoke also checks the actual Godot-imported label UV0 range, guarding against an importer promoting a tiled material UV channel into the artwork channel.

Development models are deliberately separate from the immutable SNES release lock. Build them in a local `retro-3d-library` checkout, then stage an isolated preview:

```sh
python3 scripts/prepare-media-preview.py --models-root /path/to/retro-3d-library
godot --headless --path .cache/media-preview --editor --import
RETROLIFE_REQUIRE_MEDIA_MODELS=1 godot --headless --path .cache/media-preview --script res://scripts/media_model_smoke.gd
godot --path .cache/media-preview
# Exercise routed preview controls, save collection/detail/CD views, then exit:
RETROLIFE_PREVIEW_INPUT_SMOKE=1 RETROLIFE_CAPTURE_PATH=/path/to/media.png godot --path .cache/media-preview
```

The default preview contains original synthetic titles and neutral artwork in a two-row, five-model collection. Keys 1–5 select SNES, Mega Drive, PlayStation, Nintendo 64 and NES respectively; F focuses the selection, dragging rotates it, and the wheel zooms. V flips the standalone CD between printed and dark reading faces. R restores all five models. There is no jewel case, lid or disc-removal action. Captures include both collection views, Mega Drive detail, Nintendo 64 and NES front/rear details, and both CD faces.

For locally generated Sonic the Hedgehog, Crash Bandicoot, Super Mario 64 or Super Mario Bros. examples, pass `--owner-examples /path/to/retro-3d-library/dist/owner-examples`. Each supplied example uses `<model-id>/<model-id>.glb`; models without an example use their verified neutral files. Staging copies the supplied self-contained GLBs into the disposable preview, preserves their embedded artwork and records which items have owner artwork in a local-only marker. It does not stage proprietary artwork into release inputs or add game import/emulation support. Generate these examples in the model repository using its `tools/apply_media_artwork.py` workflow.


The preview has its own user-data directory and never loads the native bridge, reads the user's library, or requests collection artwork. The generated `project.godot` is directly openable in Godot. Delete `.cache/media-preview` to undo staging. Staging validates embedded GLB resources, copies available independent notices, and records model checksums; it does not change `assets/cartridges.lock.json`, stage into release assets, or invent a remote release URL. A pre-existing output directory without the preview marker is rejected.

The expected source files are `dist/development/<id>/<id>.glb` for `snes-ntsc-u`, `mega-drive`, `playstation-1`, `nintendo-64` and `nes`. Neutral additional-model preview files must match the published app lock. The disc uses only an annular `FrontLabel`; the dark reverse is not an artwork target. Cartridge models retain their separate front/rear labels. New models use meters, +Y up, +Z front and a bottom-centered origin, normalized to a 3.3-wide by 2.4-high display envelope; the SNES scale and offset remain unchanged.

| Presentation ID | Accepted aliases | Front artwork width:height | Rear artwork width:height |
| --- | --- | --- | --- |
| `snes` | `snes-ntsc-u`, `super-nintendo` | 2:1 folded layout | Existing released rear layout |
| `mega-drive` | `megadrive`, `mega_drive`, `genesis`, `sega-genesis`, `md` | 74:67 (7 mm top fold) | 77.75:21.75 |
| `playstation-1` | `playstation`, `ps1`, `psx` | 1:1 | None (reading surface) |
| `nintendo-64` | `nintendo64`, `nintendo_64`, `n64` | 54.5:62.5 (planar, no fold) | 80.9:38.9 (photo-estimated) |
| `nes` | `nintendo-entertainment-system` | 55:97 (90 mm front and 7 mm top fold) | 78.5:31 |

Profiles use the existing bridge's `systemId` field. A pooled node rebuilds its visual only when the profile changes; GLB resources, full-detail label meshes and softened SNES materials are shared. Previous model nodes, rear artwork and label references are cleared before reusing the slot. The focused `media_model_smoke.gd` cycles all five systems on one node and checks aliases, same-profile reuse, shared meshes, front/rear artwork mapping and reset, physical canvas sizes, bounded visual count, explicit fallback, and platform-scoped collection matching. Without locally staged new models it verifies their fallback paths; `RETROLIFE_REQUIRE_MEDIA_MODELS=1` requires all five real GLBs. Nintendo 64 uses a 1024 × 1174 label canvas and NES uses 1024 × 1806, preserving the physical print proportions and NES top fold.

## Resource budgets and architecture

Godot owns presentation and input. The existing Rust bridge still owns the local library, core lifecycle, audio/video contracts and battery-save persistence. `cartridge_library.gd` specializes the existing controller so the old grid is not instantiated. `Cartridge3D.tscn` is reusable independently of library storage.

The library stores lightweight metadata and a game-ID index. It reads every 500-entry backend page, yields between pages, rejects inconsistent revisions and discards superseded refreshes. It does not silently hide entries after the first page.

The scene pool is exactly seven cartridges, or at most three visible in low-power/narrow layouts. Shared imported resources avoid copying the GLB for each title. Cartridge shell, label and rear surfaces render with a softened specular response through runtime material copies (the released GLB stays untouched), so the sharp molded seams and the label mesh's edge do not draw a bright highlight line under the showcase lights. The LRU label cache holds at most nine front entries and nine rear entries, including missing-art results; no unbounded full-library texture preload is performed. Rendering pauses behind details, search, settings, import dialogs and gameplay. The render viewport is capped near 2560 by 1440, with further reduction in low-power mode. Lighting uses three directional lights, ambient fill and a cheap generated contact shadow, without per-cartridge shadow maps or expensive postprocessing. The shadow plane stays below the transformed bounds of every visible cartridge, including maximum inspection tilt and zoom, so it cannot draw a band across the shell. Local mesh bounds are cached once; only their transforms are evaluated during motion. Pointer tilt clears when the pointer leaves the stage, and opening an overlay or losing window focus cancels unfinished pointer gestures.

The shell opens at a 2K-class window by default: `window_layout.gd` targets a 2560x1440 content area when the usable display provides it with breathing room, otherwise it opens near the full usable area and centers the window. The minimum logical window size is 1024x640 and a smaller window is not silently accepted. Window size and position persistence is planned for v0.8.0.

The responsive camera protects the centered object at narrower aspect ratios. The minimum application window is 1024 by 640 logical pixels; controls resize without shrinking all interface text, and details scroll rather than relying on a fixed-width panel. Keyboard focus remains visible and all primary commands have text alternatives. This establishes keyboard/text usability, not an untested claim of complete screen-reader support.

## Verification

```sh
python3 scripts/test-cartridge-assets.py
scripts/check.sh
# Real rendered capture with original synthetic titles; requires a graphics display:
godot --path frontend/godot-ui --script res://scripts/cartridge_library_capture.gd
```

The independent Cartridge UI workflow stages the pinned model, imports a presentation-only project, runs `cartridge_library_smoke.gd` and captures the actual rendered interface under Xvfb. Its `cartridge-ui-evidence` artifact contains logs, the model summary and ten PNG captures: default, narrow, wide, text, low-power, one game, folded-top close-up, underside inspection, rear and an empty library. These captures contain only original synthetic titles, not private ROM information, and are not committed to source history.

A separate standard hosted Apple Silicon job builds the pinned core and Rust bridge and runs headless native core/interface checks. It receives no signing credentials and is not the trusted signing machine. Its logs are saved as `cartridge-native-macos-evidence`. Workflow configuration is not itself evidence of a passed native run; record each run's actual result before claiming verification.

The smoke uses 10,000 synthetic entries to exercise pagination, stable-ID selection, rapid input, details and gameplay-return callbacks, system-specific selection, search, import insertion, missing assets, text/low-power modes, preference persistence and PNG validation. Routed keyboard, controller and mouse events are injected through Godot's input system. It checks the seven-model and nine-cache-entry bounds, measures CPU navigation p95 and rejects excessive incremental allocation. The broad hosted CPU threshold detects regressions; it is not a claim of native Apple Silicon frame rate. Existing real-core, input and battery-save tests remain required.

Native acceptance must separately record the exact Mac model, macOS/Godot/app revision, display resolution, library size, physical controller, observed frame times, audio and save restoration. Test resizing, long titles, rapid direction reversals, mouse/trackpad selection, overlays, import failures and offline startup. New code must be built and signed again before a new distributable beta is claimed. Beta.3 and later contain this carousel; beta.1 and beta.2 do not.
